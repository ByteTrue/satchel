# 对齐工具面与三模块动态开关

> 后续修正：Agent 管理工具已在 [004](004-x-将模块管理收回CLI.md) 中移除，模块管理只通过用户 CLI。以下动态管理实现与验证仅保留为历史记录。

## 目标与范围

建立三个模块 `vision`、`image`、`web-search`，把 MCP 工具名改为 Magpie 的 `analyze_image`、`generate_image`、`generate_video`、`generation_result`、`web_search`、`web_fetch`，并提供 `satchel_list_modules` / `satchel_set_module`。

本切片先打通动态注册和持久化：set 后当前进程立即更新 tools/list、发送 list_changed、直接调用受控，重启后状态保持。`generation_result` 输入改为 `id`。视频可先返回未配置错误，003 再完成能力。002 再补全部输入细节。

## 质量与验证

- 管理工具始终存在，其他工具严格按模块增删；同状态重复 set 不产生无意义变更。
- 配置写入沿用原子写/坏配置保护/脱敏；写失败不改变内存状态。
- 关闭模块后已注册调用入口不能继续发起新 provider 请求；进行中的调用按现有取消/完成语义处理。
- 官方 SDK 客户端验证 list_changed；真实 Pi 验证模块开关。
- 既有 provider 核心与 Web 行为不回归。

## 执行记录

已实现三模块注册/状态、`satchel_list_modules` / `satchel_set_module`、配置原子持久化、动态 Add/RemoveTools 和 `tools/list_changed`；管理工具始终存在。Image 统一暴露 generate_image、generate_video、generation_result，Web Search 统一控制 search/fetch。generation_result 输入已改为 `id`，图片与视频共享同一进程内任务管理器。tools/list 使用 Magpie 对齐的显式 JSON Schema（required、n=1–4、seconds=1–15）；web_search 只暴露 query，不再带 max_results。

验证：

- SDK 测试覆盖动态开关、通知、关闭后不可调用、写失败不改变状态、同状态不通知、8 种模块组合和图片/视频工具面。
- 真实 stdio 测试关闭/重开 Vision，收到 list_changed，tools/list 与磁盘配置同步变化；另起新进程验证状态恢复。
- 真实 Pi `pi mcp list` 暴露 8 个工具：6 个 Magpie 对齐工具 + 2 个管理工具。通过 satchel_set_module 关闭 Vision 后，模型不再看到 analyze_image；重新开启后恢复。
- `go test ./...`、`go vet ./...`、`go test -race ./...` 全部通过。最终独立复核 **OK（PASS）/ No issues found**，先前并发 path 与验收覆盖问题均已关闭。Issue 保持 open，关闭需用户明确授权。

## 关闭结论

Magpie 工具名/schema 与模块注册已对齐，相关 SDK/stdio 测试和独立 review 通过。原先动态 MCP 管理方案由 004 明确取代，现行 CLI-only 控制面已合回 Spec；本 Issue 保留设计历史。 经用户授权交付关闭，无隐藏遗留事项。
