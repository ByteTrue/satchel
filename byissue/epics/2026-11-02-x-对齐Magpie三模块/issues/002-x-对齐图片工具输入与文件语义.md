# 对齐图片工具输入与文件语义

## 目标与范围

完整对齐 Magpie 的 `analyze_image(image,prompt)` 与 stdio `generate_image(prompt,size,n,reference_images,quality,background,path)`，移除旧工具参数契约。

- analyze_image：单个绝对本地路径、HTTP(S) URL 或 data URL；prompt 缺省完整描述/OCR。远程与 data 输入执行现有 20 MiB、MIME、SSRF、重定向和超时预算。
- generate_image：`reference_images` 替代 `images`，n=1–4；增加 quality/background 传递；`path` 替代 filename/outputDir，支持文件或目录、相对或绝对路径、自动编号和永不覆盖。
- 配置中的默认输出目录仍为绝对路径；工具相对路径相对 MCP 进程 cwd。参考图相对路径按同一项目边界解析。
- OpenAI 完整传递 quality/background；其他协议若不支持必须明确说明，不静默声称生效。

## 质量与验证

对齐 tools/list schema、请求 payload、文件路径和部分失败；覆盖 URL/data/本地三种分析输入、path 文件/目录、n 编号、相对路径、已有文件保护。真实 stdio/Pi 重跑 Magpie 生图与真实 analyze_image。

## 执行记录

已实现：

- `analyze_image(image,prompt)`：本地绝对路径、HTTP(S)、data URL；20 MiB、魔数、SSRF/DNS/redirect/超时和签名 URL 防护，复用四协议 Vision。
- `generate_image`：reference_images、n=1–4、quality/background、path；OpenAI generations/edits 传递 quality/background，其他协议明确拒绝。
- 参考图相对路径按 MCP cwd 解析；`GenerationTarget` 裁剪复用 Magpie Target：文件/目录、相对/绝对、prompt slug、n 编号、冲突序号、实际格式扩展名纠正和永不覆盖。
- 旧 image_ask、images、filename、outputDir、task_id 工具契约已移除。

验证：本地/HTTP/data 三种分析输入、OpenAI 两路径字段、其他协议拒绝、path/相对路径/编号/冲突/部分失败、真实 stdio 与全量 Go/race/vet 均通过。并发同 path 遇 EEXIST 会重取编号；悬空 symlink 通过 Lstat 识别且不被替换，均有回归测试。

真实 Pi：analyze_image 成功读取 Magpie 生成的 PNG，返回蓝色书包、白色细节、无文字；generate_image 使用 reference_images 与 path 经本地 Magpie → boldapi/gpt-image-2.5 成功返回文件。最终独立复核 **OK（PASS）/ No issues found**，先前 EEXIST/symlink/相对路径问题均已关闭。Issue 保持 open，关闭需用户明确授权。

## 关闭结论

analyze_image 与 generate_image 的 Magpie 参数、quality/background、reference_images/path 和冲突编号已对齐；真实 Pi 生图/识图、stdio、并发/symlink 回归及最终 review 通过。文件安全经验已沉淀。 经用户授权交付关闭，无隐藏遗留事项。
