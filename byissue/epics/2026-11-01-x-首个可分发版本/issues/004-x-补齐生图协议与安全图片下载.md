# 补齐生图协议与安全图片下载

## 目标与范围

在 001 的 OpenAI/Gemini 生图主链路上补齐 Epic 选定的五种协议，并去掉 URL-only 结果与远程参考图的有界简化。

本 issue 包含：

- DashScope `POST /services/aigc/multimodal-generation/generation`：messages 中参考图在前、prompt 在后，parameters.n/size，解析 output.choices 图片。
- Ark `POST /api/v3/images/generations`：JSON model/prompt/n/size，参考图 `image: [data URI...]`，不是 multipart edits；保留尺寸映射/逐张语义中仍适用的部分。
- OpenRouter `POST /api/v1/images`：JSON prompt/n/size，编辑使用 `input_references`，解析 OpenAI 形 data。
- 本地与 HTTP(S) 参考图、provider 返回的 HTTP(S) 图片和 data URL；安全下载、图片大小/类型/超时限制。
- 配置与 setup 增加 dashscope/ark/openrouter，既有 OpenAI/Gemini 不回归。

不包含：旧 DashScope text2image 异步端点、视频、聊天模型通用网关、订阅账号、自动模型路由、额外未选择的 provider。

## 必须修改 / 需要验证 / 仍未知

- 必须修改：imagegen 协议与下载、配置 API 校验、setup、README、协议/安全/集成测试。
- 需要验证：001 的 redirect/credential 修复、文件不覆盖与 Pi 主链路不回归；002 的 netguard 语义可复用但不改变 web_fetch。
- 仍未知：provider 返回 URL 的签名参数与重定向行为；下载不得转发 provider API key，URL 中的签名不能进入错误日志。

## 质量承诺

- Agent 提供的远程参考图与 provider 返回 URL 均视为不可信网络输入：仅 HTTP(S)，拒绝非 public 地址，DNS/redirect 重新校验，限制超时和字节。
- 下载不携带配置 provider 的 Authorization/x-goog-api-key/custom secrets；跨 origin 不转发任何敏感 header。
- 远程图片仍满足 PNG/JPEG/GIF/WebP 和数量预算；base64 与 URL 混合结果不因部分形状而静默丢弃。
- 默认测试无公网；利用 fake DNS/dial/proxy 验证公网 URL 的 fake 内容，私网目标默认拒绝。

## 风险与穿刺顺序

| 顺序 | 风险 | 怎样算打通 |
| --- | --- | --- |
| 1 | 安全下载复制时丢失 DNS/redirect 或泄密 | 公网 fake 下载成功；私网/redirect 拒绝；provider key 不进入下载请求或错误 |
| 2 | 三协议看似 OpenAI 但 payload/endpoint 不同 | 三组 golden tests 锁定路径、JSON/参考图顺序、n/size 与响应 |
| 3 | base64/URL 混合结果被静默丢弃 | 混合 fixture 返回全部可用图片，单个坏 URL 的错误与部分成功语义明确 |
| 4 | 新 API 配置破坏旧路由 | 五 API Load/Resolve/setup 测试与 001 stdio/Pi 回归通过 |

## 执行记录

已实现：

- DashScope multimodal-generation、Ark `/api/v3/images/generations`、OpenRouter `/api/v1/images`，默认 base path、参考图和 n/size 与现有 TS 契约对齐；五 API 均可 Load/Resolve/setup。
- Request.Images 支持本地绝对路径和公开 HTTP(S)；OpenAI 形响应支持 base64、data URL、HTTP URL 混合，所有可用图片按顺序保留。
- `internal/imagegen/download.go` 复用 netguard.Public，DNS 全答案校验、地址 pinning、实际 dial 校验和逐 redirect 检查；最多 5 次 redirect。
- 下载不带 provider key/custom secret/cookie，redirect 清敏感 header/Referer，错误不回显签名 URL；无生产私网 bypass。
- 生成图单张 50 MiB、远程参考图 20 MiB、图片魔数校验、单次下载 2 分钟且受整体 5 分钟约束。
- 部分成功返回成功图片；完全无可用图片才报错。001 的 provider redirect 修复与不覆盖写入保持。

验证：

- `go test -count=1 ./internal/imagegen`、`go test -race -count=1 ./internal/imagegen`、`go vet ./internal/imagegen`：全部通过。
- 三协议 golden、URL/base64 混合、远程参考图、DNS rebinding/私网/redirect/proxy、签名 URL/key、大小/类型/取消均有本地测试。
- `TestSatchelStdioOpenRouterGenerateImage`：真实二进制经 OpenRouter `/api/v1/images` data-URL 响应生成正确 PNG，stderr 为空。
- OpenAI Pi 回归：扩展后重新执行独立 `pi -p`，实际调用 generate_image，fake 收到 `/v1/images/generations` 与新 prompt，返回 `/tmp/satchel-pi-smoke/images/image-20261101-142314.233923000-01.png`。

独立 review 曾 BLOCK，发现内联大小绕过、签名 URL 错误泄漏、数量预算、stdio HTTP 验收和 schema 五项。已全部修正：

- 上游自由文本中的 HTTP(S) URL 统一替换为 `[URL]`，HTTP error 与 200/no-image 均验证签名和 host 不泄漏。

- MCP schema 改为 absolute local paths or public HTTP(S) URLs。
- `SATCHEL_TEST_PUBLIC_IMAGE_URL=https://httpbin.org/image/png go test -run TestSatchelStdioOpenRouterGenerateImage -count=1 -v ./internal/cli` 已实际通过真实 stdio 公共 PNG 下载；默认运行仍为 data URL、无公网。
- 修复后全量 `go test ./...`、vet、race 通过。复核又发现大写 HTTP(S) scheme 可绕过 URL regex，已改为 case-insensitive，并给 HTTP error 与 200/no-image 增加大写用例；定向测试全部通过。最终独立复核 **OK / No issues found**，004 全部验收项 PASS。Issue 保持 open，关闭需用户明确授权。
