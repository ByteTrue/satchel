# Satchel Vision

Satchel 是用户的 Skill + MCP 伞仓库，其中的 satchel 二进制是能随 Agent 带走的通用工具箱：用户配置一次模型、搜索服务与工具开关，支持 MCP 的客户端就能按需使用这些能力。名字取“随身小挎包”之意，不绑定 Pi、某个模型供应商或某一种工具。

## 用户得到什么

用户下载对应平台的单个二进制，通过交互式命令完成配置，再把同一个命令接入 Agent。模型不直接拥有凭据配置权，只能调用用户已经开放的工具。

目标旅程是：

1. 安装并运行 `satchel setup`，只配置自己需要的 provider 和模型。
2. 独立控制识图、生图、网络搜索和网页抓取的开放状态；关闭能力不删除配置。
3. 在 Agent 中自然提出看图、生成图片、搜索或读取网页的需求。
4. 获得本地图片文件、文本分析或带来源的网页结果；长任务可以查询，失败应给出可行动的提示。
5. 更换支持 MCP 的客户端时继续使用同一个二进制和用户级配置。

## 能力版图

- **识图**：代理无视觉能力的主模型读取本地图片并回答问题。
- **图像与视频生成**：通过用户选择的模型生成或编辑图片、生成短视频，明确返回保存位置。
- **网络搜索**：在多个搜索服务间按用户配置回退，统一结果为标题、地址和摘要。
- **网页抓取**：安全读取公开网页并返回适合模型消费的正文。
- **配置与开放控制**：同一个二进制负责人工配置、脱敏状态查看和 stdio MCP 服务；Vision、Image、Web Search 三模块由用户通过 CLI 管理并持久化。

## 跨区域原则

- 单一 Go 二进制、无外部运行时、stdio 优先，不要求常驻服务。
- 模块开放状态只能由用户通过 CLI 改变，Agent 没有模块管理工具，普通工具参数也不能暗改。
- 凭据不落对话和日志；本地文件不覆盖；网络输入不能绕过 SSRF 与大小限制。
- 优先复制和裁剪经过实际使用的 Magpie 核心，不为了“全新实现”重复摸索协议。
- 产品按标准 MCP 实现；兼容声明只覆盖实际验证过的客户端。

首个可分发版本已实现、通过验收并关闭毕业。范围与切片见 [首个可分发版本 Epic](../epics/2026-11-01-x-首个可分发版本/spec.md)。长期稳定边界见 [Project Spec](../spec/index.md)。

当前已对齐 Magpie 的 Vision、Image、Web Search 三模块工具面与 CLI 管理，见 [对齐 Magpie 三模块 Epic](../epics/2026-11-02-x-对齐Magpie三模块/spec.md)；vendor Skill 与 unified/split MCP 形态见 [Satchel 技能仓库与 MCP 形态 Epic](../epics/2026-11-03-x-Satchel技能仓库与MCP形态/spec.md)。未来是否增加 HTTP 和更多客户端自动安装，仍属于后续候选。
